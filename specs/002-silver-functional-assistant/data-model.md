# Data Model: Silver Tier Functional Assistant

**Feature**: 002-silver-functional-assistant
**Date**: 2026-02-04
**Purpose**: Define data entities and their relationships for Silver tier functionality

## Entity Definitions

### 1. Email Action

**Purpose**: Represents an email detected by Gmail Watcher

**Attributes**:
- `email_id` (string): Unique Gmail message ID
- `sender` (string): Email address of sender
- `sender_name` (string): Display name of sender
- `recipient` (string): Email address of recipient (user)
- `subject` (string): Email subject line
- `body_preview` (string): First 200 characters of email body
- `timestamp` (datetime): When email was received
- `priority` (enum): urgent | normal | low
- `attachments` (array): List of attachment metadata
  - `filename` (string)
  - `size` (integer): Size in bytes
  - `mime_type` (string)
- `processed_status` (enum): pending | processed | error
- `action_file_path` (string): Path to created action file

**Validation Rules**:
- `email_id` must be unique (prevent duplicates)
- `sender` must be valid email format
- `priority` determined by keywords in subject/body
- `attachments` size total must not exceed 25MB

**State Transitions**:
```
pending → processed (when action file created)
pending → error (if processing fails)
```

**Storage**: Action file in `Needs_Action/email-{email_id}.md`

---

### 2. Draft Email

**Purpose**: Represents an email pending approval before sending

**Attributes**:
- `draft_id` (string): Unique identifier (UUID)
- `recipient` (string): Email address of recipient
- `recipient_name` (string): Display name of recipient (optional)
- `subject` (string): Email subject line
- `body` (string): Email body (HTML or plain text)
- `body_format` (enum): html | plain
- `attachments` (array): List of attachments
  - `filename` (string)
  - `path` (string): Local file path
  - `size` (integer)
- `created_timestamp` (datetime): When draft was created
- `approval_status` (enum): pending | approved | rejected
- `approved_by` (string): User who approved (optional)
- `approval_timestamp` (datetime): When approved/rejected (optional)
- `rejection_reason` (string): Why rejected (optional)
- `sent_status` (enum): not_sent | sent | failed
- `sent_timestamp` (datetime): When email was sent (optional)
- `message_id` (string): SMTP message ID after sending (optional)

**Validation Rules**:
- `recipient` must be valid email format
- `subject` must not be empty
- `body` must not be empty
- `attachments` total size must not exceed 25MB
- `approval_status` must be approved before sending

**State Transitions**:
```
pending → approved (user approves)
pending → rejected (user rejects)
approved → sent (email sent successfully)
approved → failed (email send failed)
pending → rejected (24-hour timeout)
```

**Storage**: Draft file in `Pending_Approval/email-draft-{draft_id}.md`

---

### 3. LinkedIn Post

**Purpose**: Represents a LinkedIn post pending or published

**Attributes**:
- `post_id` (string): Unique identifier (UUID before publish, LinkedIn URN after)
- `content` (string): Post text content
- `hashtags` (array): List of hashtags (strings)
- `created_timestamp` (datetime): When draft was created
- `published_timestamp` (datetime): When post was published (optional)
- `approval_status` (enum): pending | approved | rejected
- `approved_by` (string): User who approved (optional)
- `approval_timestamp` (datetime): When approved/rejected (optional)
- `rejection_reason` (string): Why rejected (optional)
- `publish_status` (enum): not_published | published | failed
- `linkedin_post_id` (string): LinkedIn URN after publishing (optional)
- `engagement_metrics` (object): Post performance (optional)
  - `views` (integer)
  - `likes` (integer)
  - `comments` (integer)
  - `shares` (integer)

**Validation Rules**:
- `content` must not exceed 3000 characters
- `hashtags` must start with # and contain no spaces
- `approval_status` must be approved before publishing

**State Transitions**:
```
pending → approved (user approves)
pending → rejected (user rejects)
approved → published (post published successfully)
approved → failed (post publish failed)
pending → rejected (24-hour timeout)
```

**Storage**: Draft file in `Pending_Approval/linkedin-post-{post_id}.md`

---

### 4. Plan

**Purpose**: Represents a multi-step task plan generated by Claude reasoning loop

**Attributes**:
- `plan_id` (string): Unique identifier (UUID)
- `task_description` (string): Original task request
- `steps` (array): List of plan steps (see Plan Step entity)
- `current_step` (integer): Index of currently executing step
- `status` (enum): draft | in_progress | completed | failed | paused
- `created_timestamp` (datetime): When plan was generated
- `started_timestamp` (datetime): When execution started (optional)
- `completed_timestamp` (datetime): When plan completed (optional)
- `created_by` (string): Who requested the plan (user or system)
- `total_steps` (integer): Number of steps in plan

**Validation Rules**:
- `steps` must have at least 1 step
- `steps` must have at most 10 steps
- `current_step` must be valid index in steps array
- Each step must have acceptance criteria

**State Transitions**:
```
draft → in_progress (execution starts)
in_progress → completed (all steps succeed)
in_progress → failed (step fails and cannot recover)
in_progress → paused (step fails, awaiting user input)
paused → in_progress (user provides input, execution resumes)
```

**Storage**: Plan file in `Plans/{plan_id}-plan.md`

---

### 5. Plan Step

**Purpose**: Represents a single step in a multi-step plan

**Attributes**:
- `step_number` (integer): Sequential step number (1-based)
- `description` (string): What this step does
- `acceptance_criteria` (string): How to verify step succeeded
- `status` (enum): pending | in_progress | completed | failed | skipped
- `started_timestamp` (datetime): When step started (optional)
- `completed_timestamp` (datetime): When step completed (optional)
- `error_message` (string): Error details if failed (optional)
- `output` (string): Step output or result (optional)
- `dependencies` (array): Step numbers that must complete first

**Validation Rules**:
- `step_number` must be unique within plan
- `description` must not be empty
- `acceptance_criteria` must not be empty
- `dependencies` must reference valid step numbers

**State Transitions**:
```
pending → in_progress (step execution starts)
in_progress → completed (step succeeds)
in_progress → failed (step fails)
pending → skipped (dependency failed)
```

**Storage**: Embedded in parent Plan file

---

### 6. Approval Request

**Purpose**: Represents an action requiring human approval

**Attributes**:
- `request_id` (string): Unique identifier (UUID)
- `action_type` (enum): email_send | linkedin_post | file_delete | other
- `action_description` (string): Human-readable description of action
- `action_details` (object): Type-specific details (JSON)
- `created_timestamp` (datetime): When request was created
- `approval_status` (enum): pending | approved | rejected | expired
- `approver` (string): User who approved/rejected (optional)
- `approval_timestamp` (datetime): When approved/rejected (optional)
- `rejection_reason` (string): Why rejected (optional)
- `expiry_timestamp` (datetime): When request expires (24 hours)
- `related_entity_id` (string): ID of related entity (draft_id, post_id, etc.)

**Validation Rules**:
- `action_type` must be valid enum value
- `action_description` must not be empty
- `expiry_timestamp` must be 24 hours after creation
- Cannot approve after expiry

**State Transitions**:
```
pending → approved (user approves)
pending → rejected (user rejects)
pending → expired (24-hour timeout)
```

**Storage**: Approval file in `Pending_Approval/{action_type}-{request_id}.md`

---

### 7. Schedule

**Purpose**: Represents a scheduled task configuration

**Attributes**:
- `schedule_id` (string): Unique identifier (UUID)
- `task_name` (string): Name of scheduled task
- `task_type` (enum): watcher | skill | custom
- `task_command` (string): Command to execute
- `cron_expression` (string): Cron-style schedule (e.g., "*/5 * * * *")
- `last_execution` (datetime): When task last ran (optional)
- `next_execution` (datetime): When task will run next
- `status` (enum): active | paused | disabled
- `execution_count` (integer): Total number of executions
- `failure_count` (integer): Number of failed executions
- `created_timestamp` (datetime): When schedule was created
- `platform` (enum): windows | linux | mac

**Validation Rules**:
- `cron_expression` must be valid cron syntax
- `task_command` must be executable
- `status` must be active for execution

**State Transitions**:
```
active → paused (user pauses)
paused → active (user resumes)
active → disabled (user disables)
disabled → active (user re-enables)
```

**Storage**: Schedule config in `config/scheduler_config.json`

## Entity Relationships

```
Email Action (1) → (1) Action File
Draft Email (1) → (1) Approval Request
LinkedIn Post (1) → (1) Approval Request
Plan (1) → (many) Plan Steps
Approval Request (1) → (0..1) Draft Email
Approval Request (1) → (0..1) LinkedIn Post
Schedule (1) → (many) Execution Logs
```

## Data Flow

### Email Monitoring Flow
```
Gmail API → Email Action → Action File (Needs_Action/) → Claude Processing
```

### Email Sending Flow
```
Action File → Draft Email → Approval Request (Pending_Approval/) → User Approval → MCP Email Server → Sent Email Log
```

### LinkedIn Posting Flow
```
Action File → LinkedIn Post → Approval Request (Pending_Approval/) → User Approval → LinkedIn API → Post Log
```

### Planning Flow
```
Action File (complex task) → Claude Reasoning → Plan → Plan Steps → Execution → Dashboard Update
```

### Scheduling Flow
```
Schedule Config → Scheduler Process → Task Execution → Execution Log
```

## Storage Format

All entities stored as Markdown files with YAML frontmatter:

```markdown
---
entity_type: email_action
email_id: "abc123"
sender: "client@example.com"
subject: "URGENT: Meeting tomorrow"
priority: urgent
timestamp: 2026-02-04T10:30:00Z
processed_status: processed
---

# Email Action: URGENT: Meeting tomorrow

**From**: client@example.com
**Received**: 2026-02-04 10:30 AM

## Body Preview
Hi, we need to discuss the project urgently. Can we meet tomorrow at 2 PM?

## Attachments
- proposal.pdf (1.2 MB)

## Action Required
Draft response and schedule meeting.
```

## Validation Strategy

1. **Schema Validation**: Validate YAML frontmatter against entity schema
2. **Business Rules**: Enforce state transitions and validation rules
3. **Referential Integrity**: Verify related entities exist
4. **Data Sanitization**: Escape HTML, validate email addresses, check file paths
5. **Error Handling**: Log validation errors, move invalid files to error folder
